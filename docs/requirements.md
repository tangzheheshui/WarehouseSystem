## 1. 目标与适用范围

系统为 Web 版仓库管理系统，产品名「**万顺WMS仓库管理系统**」。平台由万顺运营，服务多家公司：万顺通过控制台创建公司，每家公司使用独立子域名与独立数据库文件，公司内可创建多个项目；数据按公司物理隔离。本次聚焦 PC 端 Web 系统，不开发 APP 端与扫码功能，除非客户明确特殊需求。

## 2. 角色与权限

| 功能 | 管理员 | 项目管理员 |
| --- | --- | --- |
| 商品信息录入与维护 | 可以 | 不可以 |
| 仓库信息管理 | 可以 | 不可以 |
| 创建项目并绑定仓库/库区 | 可以 | 不可以 |
| 创建用户并授权项目 | 可以 | 不可以 |
| 设置项目可用商品 | 可以 | 不可以 |
| 入库、出库（导入/手动） | 不可以 | 可以 |
| 库存查询和导出 | 不可以 | 可以 |
| 拣货单 | 不可以 | 可以 |
| 模板管理 | 不可以 | 可以 |
| 操作日志 | 不可以 | 可以 |

### 2.1 管理员

- 创建、修改、停用商品；维护商品分类、单位、重量、体积、保质天数。
- 创建仓库、库区、货区、货位。
- 创建项目、绑定唯一仓库与库区、维护项目状态和项目可用商品。
- 创建用户、分配角色、授权项目、重置密码、停用用户。
- 对空项目执行历史库存初始化。
- 管理员不能执行项目作业：入库、出库、模板维护、拣货、库存查询和项目日志查询。
- 商品维护独立于日常出入库操作，普通操作员不可修改基础数据。

### 2.2 项目管理员

- 下载、修改、停用当前项目模板。
- 上传入库、出库 Excel，或页面手动录入。
- 查询和导出当前项目库存（汇总/明细）。
- 查看、打印和完成当前项目拣货单。
- 查看当前项目操作日志。
- 项目管理员不能维护商品、仓库、项目和用户。

### 2.3 授权规则

1. 授权关系以 `user_projects` 为准。
2. 项目管理员访问项目时必须重新校验项目授权和项目状态。
3. 取消授权后，已有登录 token 不能继续访问该项目。
4. 停用用户后，已有登录 token 立即失效。
5. 重置密码后，所有旧 token 失效，新密码首次登录后强制修改。

### 2.4 平台管理员与账号资产（V5）

三级账号体系：万顺平台管理员 → 公司管理员 → 项目管理员。

1. 万顺平台管理员只在万顺控制台登录，不属于任何公司；负责创建公司（配置公司前缀、公司名称、公司管理员初始账号）、停用/启用公司、应急重置公司管理员密码；不进入公司业务系统，不参与业务操作。
2. 公司管理员账号由万顺在控制台创建，初始密码一次性显示交给公司；此后账号日常使用归公司。
3. 账户是公司资产：公司内部用户由公司管理员创建、授权、重置密码、停用，万顺不介入；万顺只持有公司管理员这一个入口。
4. 密码只重置、不找回：任何人可修改本人密码；全系统没有自助找回通道——普通用户遗忘密码由公司管理员重置，公司管理员遗忘密码由万顺平台管理员在控制台重置；重置后旧 token 全部失效，首次登录强制修改密码。
5. 每家公司至少一名公司管理员，可创建多名；公司管理员之间可互相重置密码。

## 3. 基础档案

### 3.1 商品

- 字段：货品编号、货品名称、货品分类、规格、单位、单件重量、体积、保质天数、状态。
- 货品编号公司唯一；编号和名称必填；单位须与出入库单据一致。
- 停用商品不能参与新入库、新出库；历史单据和库存仍保留商品快照或引用。
- 操作流程：新品先由管理员维护到系统，并添加到对应项目（项目可用商品）后，方可进行出入库操作。

### 3.2 仓库货位

- 层级固定为仓库、库区、货区、货位；完整货位按四段展示。
- 仓库名称公司唯一；同仓库下完整货位唯一。
- 停用仓库或货位不能用于新入库。
- 货区/货位属于仓库内部结构，不与项目直接强绑定，但操作时遵循所属仓库逻辑。

### 3.3 项目

- 字段：项目名称、绑定仓库、绑定库区、状态、说明。
- 项目名称公司唯一；创建项目时绑定唯一的仓库和库区；项目已有库存后不允许更换仓库/库区。
- 项目状态为启用、停用；停用项目不能入库、出库、修改模板；历史库存、单据、模板和日志仍按项目保留。
- 管理员分配项目权限后，用户只能在绑定仓库/库区内作业。

## 4. 模板规则

1. 模板分入库、出库两类，按项目隔离；每个项目创建时初始化两类模板，版本号为 1。
2. 项目管理员可修改中文列名和非系统必填字段配置；系统必填字段不能改为非必填。
3. 每次保存成功后版本号加一；停用模板后不能下载和导入，历史单据保留原版本号。
4. 导入解析以当前项目当前版本模板列名为准。
5. 模板下载后在系统外使用 Excel 编辑再上传；系统不提供内嵌 Excel 编辑器。

## 5. 入库管理

### 5.1 模板字段

入库支持 Excel 模板导入和系统界面手动录入两种方式。模板必填字段精简如下，其余非必要字段可隐藏或移除：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 入库通知单号 | 是 | 用户自定义，全系统唯一，不可重复 |
| 入库日期 | 是 | 实际入库时间 |
| 货品编号 | 是 | 核心索引，输入后系统自动带出货品名称、规格、单位 |
| 品质标记 | 否 | 默认为良品，特殊情况可改为扣留 |
| 生产批号 | 是 | 用于批次管理 |
| 生产日期 | 是 | |
| 到期日期 | 否 | 部分项目（如电池）需要；留空时按生产日期+商品保质天数自动计算 |
| 数量 | 是 | 正整数 |
| 单位 | 是 | 与数量配合使用，须与商品档案单位一致 |
| 货位 | 是 | 仓管按实际空闲库位填写，系统在项目绑定的仓库/库区内解析 |
| 采购单号 | 否 | 按项目需要保留 |
| 备注 | 否 | 按项目需要保留 |

说明：

1. 库区/仓库在管理员创建项目并授权时已固定，操作人员无需在入库表中填写，系统自动关联。
2. 规格包含在货品编号对应属性中，模板不单独列示。
3. 货位在项目绑定的仓库、库区内解析；若同名货位不唯一，须使用 `货区/货位` 格式填写。
4. 到期日期留空时，系统按“生产日期 + 商品保质天数”自动计算；商品未维护保质天数时允许为空。

### 5.2 校验与输出

1. 货品必须已建档、启用且已添加到当前项目。
2. 入库通知单号唯一；同一文件内与历史单据均不可重复。
3. 同商品、批次、货位的多行数量累计；生产日期、到期日期、品质、采购单号等必须一致。
4. 任一行错误时整单拒绝，不生成入库单、库存、流水或日志。
5. 成功后生成状态为完成的入库单、库存批次明细、正数库存流水和操作日志。

## 6. 出库管理

### 6.1 模板字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 配货单号（出库通知单号） | 是 | 用户自定义，全系统唯一，不可重复 |
| 出库日期 | 是 | |
| 货品编号 | 是 | 核心索引 |
| 品质 | 否 | 默认良品 |
| 生产批号 | 否 | 部分项目需要；填写时仅从该批次出库 |
| 生产日期 | 否 | 填写时仅从该生产日期批次出库 |
| 数量 | 是 | 正整数 |
| 单位 | 是 | 须与商品档案单位一致 |
| 指定货位 | 否 | 填写时仅从该货位出库；留空按先进先出自动分配 |
| 收货方 | 否 | 打印拣货单表头使用 |
| 备注 | 否 | |

### 6.2 校验与分配

1. 只校验和扣减当前项目库存；同货品、同约束（货位/批次/生产日期/品质）的多行数量先累计再校验。
2. 同一配货单中部分商品需指定货位、部分不需时，须分多行录入，分别指定或不指定货位。
3. 指定货位时仅从该货位扣减，库存不足整单拒绝；留空时按先进先出（入库日、最后入库时间、库存 ID 顺序）自动分配最旧日期库存。
4. 品质为扣留、禁止出库为是的批次不计入可用库存。
5. 可用库存 = 库存总数 - 分拣占用数 - 移动占用数；不足时整单拒绝。
6. 出库成功立即扣减库存，出库流水记录负数；出库单初始状态为待拣货，系统同时生成拣货单和拣货明细。
7. 拣货完成只把拣货单和出库单状态改为完成，不再次扣减库存。

## 7. 移库管理

同一项目（绑定唯一仓库与库区）内，把某商品某批次从源货位移动到目标货位。

### 7.1 模板字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 移库单号 | 是 | 用户自定义，全系统唯一，不可重复；一次导入一个文件一个单号 |
| 移库日期 | 是 | |
| 货品编号 | 是 | 须已建档、启用并添加到当前项目 |
| 生产批号 | 是 | 源货位须存在该批次库存 |
| 数量 | 是 | 正整数，不超过源货位可用库存 |
| 单位 | 是 | 须与商品档案单位一致 |
| 源货位 | 是 | 项目仓库+库区内解析；重名货位须用 货区/货位 格式 |
| 目标货位 | 是 | 同上，且不能与源货位相同 |
| 备注 | 否 | |

### 7.2 规则

1. 仅项目管理员可操作，复用项目授权与状态校验；支持 Excel 导入与手动录入。
2. 一步生效：提交通过校验后立即源货位扣减、目标货位增加，无两段式确认；任一行失败整单拒绝、全部回滚。
3. 可用库存 = 库存总数 - 分拣占用数 - 移动占用数；不足时整单拒绝。
4. 目标货位已存在同商品、同批次库存时，生产日期、到期日期、入库日、品质、采购单号须与源批次一致方可合并（数量累加），否则整单拒绝；目标行不存在时新建，批次属性从源库存行带入，占用数归零。
5. 品质为扣留、禁止出库为是的批次允许移库，品质与禁止出库标记随批次带到目标货位。
6. 源货位库存减到 0 保留 0 库存行，与出库行为一致。
7. 每行生成两条库存流水：源货位 move_out 负数、目标货位 move_in 正数；审计日志记 stock.move。
8. 同一移库单内支持链式移库（如 A→B、B→C），按行顺序执行。
9. 导入限额（≤500 行、≤5MB）、错误明细导出与入库/出库一致。
10. 移库为第三类项目模板，支持自定义列、版本化和停启用，与入库/出库模板管理一致；手动录入的货位、货品、批次字段提供已有库存联想。

## 8. 拣货单（分拣单）打印

审核通过后生成 A4 格式拣货单：

1. 分组：以配货单号为单位打印；不同配货单必须分开打印，一个配货单内容过多时分页打印并标注页码（如 1-1、1-2）。
2. 表头：分拣组号（系统自动生成）、出库通知单号、出货日期、收货方。
3. 表格列：序号、货品编号、货品名称、生产日期、生产批号、品质、货位、分拣总数、单位。
4. 排序：提供两种排序选项供用户选择后打印或导出：按货位排序（按仓库/库区/货区/货位路径拣货）、按货品编号排序（集中拣选同一商品）。

## 9. 库存查询

系统提供两种维度查询视图，支持用户自定义显示/隐藏列（按视图保存到本地，不影响其他用户）：

### 9.1 库存汇总查询

- 维度：以货品编号为唯一键聚合。
- 展示字段：货品编号、货品名称、库存总数量、可用库存、单位、所属仓库。

### 9.2 库存明细查询

- 维度：以货位为维度展示批次分布。
- 展示字段：仓库、库区、货区、货位、货品编号、货品名称、生产批号、生产日期、到期日期、库存数量、分拣占用、移动占用、可用库存、单位、品质、入库日期。

### 9.3 规则

1. 库存按项目、商品、货位、批次隔离。
2. 查询条件支持仓库、库区、货区、货位、商品、批次、品质、禁止出库及日期范围。
3. 查询结果不保存、不生成结果单编号；导出内容与当前视图、当前查询条件一致。

## 10. 历史库存初始化

- 仅管理员可执行；仅无库存项目可执行；每个项目只能执行一次。
- 系统自动补齐不存在的商品、仓库和货位，并自动关联到项目。
- 保留库存总数、分拣占用、移动占用、品质、禁止出库、采购单号和日期；忽略源文件可用库存列，由系统重算。
- 成功后生成历史导入单、库存和库存流水。

## 11. 前端与部署（V5 目标架构）

- 平台为单服务器单进程多公司：一个应用进程按请求子域名前缀（Host）分发到对应公司的数据库文件；每家公司仍是独立 SQLite 数据库，隔离边界不变。
- 公司访问地址为独立子域名 `<公司标识>.wms.tangzheheshui.cn`（公司放子域名前缀）；应用统一部署在子域名根路径，页面静态资源必须使用相对路径。
- 前端 API 按当前路径推导基址，根路径部署时基址为空，不得出现双斜杠；登录态和项目选择按基址隔离。
- 公司标识使用英文小写字母、数字或连字符，同时作为子域名前缀和数据目录名。
- DNS 使用泛解析 `*.wms` 指向服务器；HTTPS 使用一张 `*.wms` 泛域名证书（DNS-01 验证，需 DNSPod API Token），由 acme/certbot 定时续期。
- 万顺控制台部署在 `console.wms.tangzheheshui.cn`：平台管理员登录后创建公司、停用/启用公司、应急重置公司管理员密码。
- 登录页显示系统名「万顺WMS仓库管理系统」与本公司名称；公司名称存于公司注册数据，公司管理员可改。
- 旧路径 `http://<服务器IP>/<公司标识>/` 永久 308 跳转到对应子域名。
- 现有独立进程部署方式（scripts/deploy.sh）保留为首装与应急工具，日常开公司一律走控制台。实施方案详见附录 A。

## 12. 非功能需求

1. 单次 Excel 导入不超过 500 行、5MB；历史 CSV 不超过 5000 行、12MB。
2. 密码 PBKDF2 加密存储，会话 24 小时有效；接口校验登录、角色和项目授权。
3. 项目管理员不能通过修改请求参数访问未授权项目。
4. 页面、模板、导出文件的用户可见字段使用中文名称。
5. 操作日志记录项目、时间、操作人、操作类型和内容，不允许修改或删除。

## 13. 测试需求

1. 每次修改代码必须运行与修改范围对应的自动化用例；提交前运行全量 `./scripts/run-tests.sh`。
2. 双角色自动化验收在临时库中自动创建 `zhangsan` 和 `liuhaifeng`，不依赖真实环境账号；测试必须使用临时数据库和构造数据，禁止在生产库执行破坏性测试。
3. 入库、出库 Excel 必须由当前项目模板表头生成；本地 `tests/data/excel/` 样例用于人工检查，自动化用例运行时按当前模板重新生成 xlsx。
4. 权限、项目隔离、原子回滚和 FIFO 是 P0 回归项。
5. `acme` 端到端验收是部署后的可选检查，不在日常全量回归中执行；数据使用 `AUTO-` 前缀和唯一时间戳，单据保留追溯，不清理已有业务数据。
6. V5 多公司项：按 Host 分发后跨公司数据不可见（A 公司会话访问 B 公司子域名必须无效）；控制台接口仅平台管理员可访问；公司创建、停用启用、管理员重置流程须可自动化验收。

## 14. 验收标准

1. 管理员能维护商品、仓库货位、项目（绑定仓库/库区）、项目可用商品、项目管理员和项目授权。
2. 管理员页面不显示模板、入库、出库功能；项目管理员只能访问被授权项目。
3. A 项目用户不能查询、导入、导出 B 项目数据。

## 附录 A：万顺控制台与多公司架构方案（V5）

| 项目 | 内容 |
| --- | --- |
| 状态 | 已上线（2026-10-14 应用层实现并部署；泛域名证书待 DNSPod Token） |
| 日期 | 2026-10-14 |
| 关联 | 需求见本文档 §1、§2.4、§10 |

> 实现说明：`server/platform_registry.py`（公司注册表 + 控制台账号）、`server/app.py`（按 Host 分发与控制台路由）、`static/console.html|js`（控制台前端）；启动方式 `python server/main.py --platform --domain wms.tangzheheshui.cn`。自动化验收见 `tests/cases/test_platform.py`（PLT-01～16）。

### 1. 目标

- **开公司不碰服务器**：万顺在网页控制台填表（公司前缀、公司名称、公司管理员账号）即可上线一家新公司，全程无 SSH、无脚本。
- **隔离不降级**：每家公司仍是独立 SQLite 数据库文件；不把所有公司塞进同一张大表，隔离边界与现有单公司部署一致。
- **基础设施一次配好**：泛解析 + 一张 `*.wms` 泛域名证书，之后新增公司零 DNS、零证书操作。

### 2. 目标架构

```text
        DNS：*.wms.tangzheheshui.cn → 193.112.26.217（已就位）
                          │
        nginx（一张 *.wms 泛域名证书，一次配好不再动）
          │                              │
  console.wms.…（万顺控制台）    acme.wms.… / bcompany.wms.… / …
          │                              │
          └──────── 同一个应用进程（127.0.0.1:8000）──────────
                          按 Host 前缀选数据库
                    ├─ data/companies/acme/warehouse.db
                    ├─ data/companies/bcompany/warehouse.db
                    └─ 公司注册表（前缀、名称、状态）
```

### 3. 进程与数据模型

- 一个应用进程（systemd 服务 `wms-platform`）监听 `127.0.0.1:8000`，替代现在「每公司一个进程」。
- 每请求解析 Host：取子域名前缀（`acme.wms.tangzheheshui.cn` → `acme`），查公司注册表得到数据库路径，请求生命周期内 `db.connect` 使用该路径。现有代码每请求新建连接（app.py 的 dispatch），service 层全部以 `connection` 为参数，**业务表结构零改动**。
- 公司注册表 `data/platform.json`：
  - `companies`: `{prefix, name, status(active|disabled), db_path, created_at}`
  - `platform_admin`: 登录名 + 密码哈希（首启由环境变量 `WMS_PLATFORM_ADMIN_USERNAME/PASSWORD` 初始化，与业务库 PBKDF2 同套加密）
- 会话 token 本就存在各公司库内，天然跨公司无效；控制台会话单独存。
- 控制台是同进程内的特殊 Host 分支：Host 为 `console.wms.tangzheheshui.cn` 时进入控制台路由，不与业务接口混用。

### 4. 控制台功能

| 功能 | 说明 |
| --- | --- |
| 登录 | 平台管理员账号密码；密码规则与业务侧一致（8-20 位字母+数字，5 次锁定） |
| 创建公司 | 表单字段：公司前缀（小写字母/数字/连字符，≤32，保留字禁止，唯一校验）、公司名称（登录页显示，后续可改）、公司管理员姓名全拼 + 初始密码（默认自动生成，**保存后一次性显示**） |
| 公司列表 | 前缀、公司名称、状态、创建时间、管理员用户名 |
| 停用/启用 | 停用后该公司全部子域名请求返回「已停用」提示页；数据完整保留 |
| 重置公司管理员密码 | 选公司 → 重置 → 新密码一次性显示；旧 token 全部失效（应急通道，对应「不能找回」） |
| 删除公司 | 二期预留：需双重确认 + 自动备份后软删；首期不做 |

### 5. 品牌规范

- 系统名固定：**万顺WMS仓库管理系统**（登录页主标题、浏览器 title）。
- 登录页第二行显示本公司名称（来自公司注册表 `name`）；公司管理员可在系统设置里修改本公司名称。
- 静态资源保持相对路径引用。

### 6. 证书与 DNS（一次性基础设施）

1. 万顺在 DNSPod 控制台创建 **API Token**（仅授予 `tangzheheshui.cn` 的 DNS 权限），提供给服务器。
2. 服务器用 acme.sh（内置 DNSPod 支持）或 certbot-dns-dnspod，以 DNS-01 方式签发 `*.wms.tangzheheshui.cn`（SAN 含 `wms.tangzheheshui.cn` 和 `console.wms.tangzheheshui.cn`）。
3. nginx 收敛为单站点配置：console Host → 控制台；`*.wms` 与裸 `wms` Host → 应用；80 端口跳 443；保留旧路径 `/<公司标识>/` 的 308 跳转。
4. 续期由 acme.sh/certbot 定时任务完成，续期后自动 reload nginx。

### 7. 数据迁移（现有 acme 实例）

1. 迁移前 `sqlite3 .backup` 全量备份。
2. `/opt/wms-acme/data/warehouse.db` → `data/companies/acme/warehouse.db`；注册表登记 `prefix=acme`、`name=`（客户公司名，admin 可后改）。
3. 旧目录与 `wms-acme.service` 保留但 stop + disable，作为回滚开关。
4. 验证清单：登录正常；商品 50、库存 810 条对账一致；佳能/高乐氏项目单据与日志可见；拣货单打印正常。

### 8. 实施顺序

1. **泛域名证书 + nginx 收敛**（纯基础设施，不动应用代码）
2. **应用 Host 分发 + 公司注册表**（含 acme 迁移与对账验证）
3. **控制台**（登录、建公司、列表、停用启用、重置管理员密码）
4. **品牌**（登录页系统名 + 公司名、浏览器 title）
5. **测试**：跨公司隔离、控制台鉴权、重置流程（requirements §12 第 6 条），全量回归现有 29 用例

### 9. 风险与回滚

| 风险 | 对策 |
| --- | --- |
| 所有公司共用一个进程，一家故障全停 | 单机 SQLite 场景可接受；systemd 自动重启；数据独立，可单独恢复某家公司 |
| 泛域名证书签发失败 | 保留现有按公司单证书配置作为回退 |
| 数据迁移出错 | 迁移前备份；旧实例 stop 但保留，切回旧 nginx 配置即整体回滚 |
| 控制台是高权限入口 | 独立子域名 + 强密码 + 锁定策略；PENDING-09 决定是否加二次验证 |

### 10. 明确不做的事

- 不做公司间数据共享或平台级汇总报表。
- 不做公司自注册、自助开通（开公司永远是万顺行为）。
- 不做控制台操作公司业务数据（控制台只管公司与账号）。
- scripts/deploy.sh 保留为首装与应急工具，不再用于日常开公司。
