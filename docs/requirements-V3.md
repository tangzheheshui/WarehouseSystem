## 2. 角色边界

### 2.1 管理员

管理员负责公司级基础数据和账号：

- 创建、修改、停用商品。
- 创建仓库、库区、货区、货位。
- 创建项目和维护项目状态。
- 创建用户、分配角色、授权项目、重置密码、停用用户。
- 对空项目执行历史库存初始化。

管理员不能执行项目作业：入库、出库、模板维护、拣货、库存查询和项目日志查询。

### 2.2 项目管理员

项目管理员只能在其被授权的活动项目内作业：

- 下载、修改、停用当前项目模板。
- 上传入库、出库 Excel。
- 查询和导出当前项目库存。
- 查看和完成当前项目拣货单。
- 查看当前项目操作日志。

项目管理员不能维护商品、仓库、项目和用户。

### 2.3 授权规则

1. 授权关系以 `user_projects` 为准。
2. 项目管理员访问项目时必须重新校验项目授权和项目状态。
3. 取消授权后，已有登录 token 不能继续访问该项目。
4. 停用用户后，已有登录 token 立即失效。
5. 重置密码后，所有旧 token 失效，新密码首次登录后强制修改。

## 3. 基础档案规则

### 3.1 商品

- 字段：货品编号、货品名称、规格、标准单位、状态。
- 货品编号公司唯一。
- 货品编号和名称必填。
- 停用商品不能参与新入库、新出库。
- 历史单据和库存仍保留商品快照或引用。

### 3.2 仓库货位

- 层级固定为仓库、库区、货区、货位。
- 完整货位按四段展示。
- 仓库名称公司唯一。
- 同仓库下完整货位唯一。
- 停用仓库或货位不能用于新入库。

### 3.3 项目

- 项目名称公司唯一。
- 项目状态为启用、停用。
- 停用项目不能入库、出库、修改模板。
- 停用项目的历史库存、单据、模板、日志保留。

## 4. 模板规则

1. 模板分入库、出库两类，按项目隔离。
2. 每个项目创建时初始化两类模板，版本号为 1。
3. 项目管理员可修改中文列名和非系统必填字段配置。
4. 系统必填字段不能改为非必填。
5. 每次保存成功后版本号加一。
6. 停用模板后不能下载和导入，历史单据保留原版本号。
7. 导入解析以当前项目当前版本模板列名为准。

模板下载后由用户在系统外使用 Excel 编辑，再上传到系统。系统只负责模板生成、上传校验、导入或拒绝，不提供内嵌 Excel 编辑器。商品和仓库档案当前仍由管理员在系统内单条维护。

## 5. 入库规则

### 5.1 输入

入库模板包含货品编号、货品名称、规格、标准单位、生产批号、生产日期、保质期、入库日、标准单位数、仓库、库区、货区、货位、品质标记、采购单号、备注。

### 5.2 校验

- 商品必须存在且启用。
- 商品名称、规格、标准单位必须与档案一致。
- 仓库、库区、货区、货位必须存在且启用。
- 日期必须为 `yyyy-MM-dd`。
- 数量必须为正整数。
- 品质标记必填。
- 同商品、批次、货位多行数量累计。
- 同商品、批次、货位多行的生产日期、保质期、入库日、品质、采购单号必须一致。
- 任一行错误时整单拒绝，不生成入库单、库存、流水或日志。

### 5.3 输出

成功后生成：

1. 一张状态为完成的入库单。
2. 库存批次明细。
3. 正数库存流水。
4. 入库操作日志。

到期日期自动等于生产日期加保质期天数，不在 Excel 中填写。

## 6. 出库与拣货规则

### 6.1 出库前校验

- 只校验和扣减当前项目库存。
- 同货品多行数量先累计再校验。
- 可用库存等于库存总数减分拣占用数减移动占用数。
- 品质为扣留的批次不计入可用库存。
- 禁止出库为是的批次不计入可用库存。
- 可用库存不足时整单拒绝。

### 6.2 分配和扣减

- 按入库日、最后入库时间、库存 ID 的顺序先进先出分配。
- 上传出库成功时立即扣减库存。
- 出库流水记录负数。
- 出库单初始状态为待拣货。
- 系统同时生成拣货单和拣货明细。

### 6.3 拣货完成

- 拣货完成只把拣货单和出库单状态改为完成。
- 拣货完成不再次扣减库存。
- 拣货单、出库单和日志均按项目隔离。

## 7. 库存、查询和日志

1. 库存按项目、商品、货位、批次隔离。
2. 查询条件支持仓库、库区、货区、货位、商品、批次、品质、禁止出库。
3. 查询结果不保存，不生成结果单编号。
4. 导出内容与当前查询结果一致。
5. 操作日志记录项目、时间、操作人、操作类型和内容。
6. 日志不允许修改或删除。

## 8. 历史库存初始化

- 仅管理员可执行。
- 仅无库存项目可执行。
- 每个项目只能执行一次。
- 系统自动补齐不存在的商品、仓库和货位。
- 保留库存总数、分拣占用、移动占用、品质、禁止出库、采购单号和日期。
- 忽略源文件可用库存列，由系统重算。
- 成功后生成历史导入单、库存和库存流水。

## 9. 前端和部署

- 公司访问路径固定为 `/公司标识/`。
- 页面静态资源必须使用相对路径。
- 前端 API 必须拼接为 `/公司标识/api/...`，不得出现双斜杠。
- 登录态和项目选择按公司前缀隔离。
- 每家公司独立目录、数据库、systemd 服务和内部端口。
- 生产部署后必须执行只读健康检查。

## 10. 测试需求

1. 每次修改代码必须运行与修改范围对应的自动化用例。
2. 提交前运行全量 `./tests/scripts/run.sh`。
3. 双角色自动化验收在临时库中自动创建 `zhangsan` 和 `liuhaifeng`，不依赖任何真实环境账号。
4. 自动化测试必须使用临时数据库和测试构造数据。
5. 禁止在生产库执行破坏性测试。
6. 入库、出库 Excel 必须由当前项目模板表头生成。
7. 权限、项目隔离、原子回滚和 FIFO 是 P0 回归项。
8. `acme` 端到端验收是部署后的可选检查，不在日常全量回归中执行；数据使用 `AUTO-` 前缀和唯一时间戳，单据保留追溯，不清理已有业务数据。
9. 本地 `tests/data/excel/` 样例用于人工检查，自动化用例必须在运行时按当前模板重新生成 xlsx。
