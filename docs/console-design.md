# 万顺控制台与多公司架构方案（V5）

| 项目 | 内容 |
| --- | --- |
| 状态 | 方案已确认，待开发 |
| 日期 | 2026-10-14 |
| 关联 | 需求见 [requirements.md](requirements.md) §1、§2.4、§10 |

## 1. 目标

- **开公司不碰服务器**：万顺在网页控制台填表（公司前缀、公司名称、公司管理员账号）即可上线一家新公司，全程无 SSH、无脚本。
- **隔离不降级**：每家公司仍是独立 SQLite 数据库文件；不把所有公司塞进同一张大表，隔离边界与现有单公司部署一致。
- **基础设施一次配好**：泛解析 + 一张 `*.wms` 泛域名证书，之后新增公司零 DNS、零证书操作。

## 2. 目标架构

```text
        DNS：*.wms.tangzheheshui.cn → 193.112.26.217（已就位）
                          │
        nginx（一张 *.wms 泛域名证书，一次配好不再动）
          │                              │
  console.wms.…（万顺控制台）    acme.wms.… / bcompany.wms.… / …
          │                              │
          └──────── 同一个应用进程（127.0.0.1:8000）──────────
                          按 Host 前缀选数据库
                    ├─ data/companies/acme/warehouse.db
                    ├─ data/companies/bcompany/warehouse.db
                    └─ 公司注册表（前缀、名称、状态）
```

## 3. 进程与数据模型

- 一个应用进程（systemd 服务 `wms-platform`）监听 `127.0.0.1:8000`，替代现在「每公司一个进程」。
- 每请求解析 Host：取子域名前缀（`acme.wms.tangzheheshui.cn` → `acme`），查公司注册表得到数据库路径，请求生命周期内 `db.connect` 使用该路径。现有代码每请求新建连接（app.py 的 dispatch），service 层全部以 `connection` 为参数，**业务表结构零改动**。
- 公司注册表 `data/platform.json`：
  - `companies`: `{prefix, name, status(active|disabled), db_path, created_at}`
  - `platform_admin`: 登录名 + 密码哈希（首启由环境变量 `WMS_PLATFORM_ADMIN_USERNAME/PASSWORD` 初始化，与业务库 PBKDF2 同套加密）
- 会话 token 本就存在各公司库内，天然跨公司无效；控制台会话单独存。
- 控制台是同进程内的特殊 Host 分支：Host 为 `console.wms.tangzheheshui.cn` 时进入控制台路由，不与业务接口混用。

## 4. 控制台功能

| 功能 | 说明 |
| --- | --- |
| 登录 | 平台管理员账号密码；密码规则与业务侧一致（8-20 位字母+数字，5 次锁定） |
| 创建公司 | 表单字段：公司前缀（小写字母/数字/连字符，≤32，保留字禁止，唯一校验）、公司名称（登录页显示，后续可改）、公司管理员姓名全拼 + 初始密码（默认自动生成，**保存后一次性显示**） |
| 公司列表 | 前缀、公司名称、状态、创建时间、管理员用户名 |
| 停用/启用 | 停用后该公司全部子域名请求返回「已停用」提示页；数据完整保留 |
| 重置公司管理员密码 | 选公司 → 重置 → 新密码一次性显示；旧 token 全部失效（应急通道，对应「不能找回」） |
| 删除公司 | 二期预留：需双重确认 + 自动备份后软删；首期不做 |

## 5. 品牌规范

- 系统名固定：**万顺WMS仓库管理系统**（登录页主标题、浏览器 title）。
- 登录页第二行显示本公司名称（来自公司注册表 `name`）；公司管理员可在系统设置里修改本公司名称。
- 静态资源保持相对路径引用。

## 6. 证书与 DNS（一次性基础设施）

1. 万顺在 DNSPod 控制台创建 **API Token**（仅授予 `tangzheheshui.cn` 的 DNS 权限），提供给服务器。
2. 服务器用 acme.sh（内置 DNSPod 支持）或 certbot-dns-dnspod，以 DNS-01 方式签发 `*.wms.tangzheheshui.cn`（SAN 含 `wms.tangzheheshui.cn` 和 `console.wms.tangzheheshui.cn`）。
3. nginx 收敛为单站点配置：console Host → 控制台；`*.wms` 与裸 `wms` Host → 应用；80 端口跳 443；保留旧路径 `/<公司标识>/` 的 308 跳转。
4. 续期由 acme.sh/certbot 定时任务完成，续期后自动 reload nginx。

## 7. 数据迁移（现有 acme 实例）

1. 迁移前 `sqlite3 .backup` 全量备份。
2. `/opt/wms-acme/data/warehouse.db` → `data/companies/acme/warehouse.db`；注册表登记 `prefix=acme`、`name=`（客户公司名，admin 可后改）。
3. 旧目录与 `wms-acme.service` 保留但 stop + disable，作为回滚开关。
4. 验证清单：登录正常；商品 50、库存 810 条对账一致；佳能/高乐氏项目单据与日志可见；拣货单打印正常。

## 8. 实施顺序

1. **泛域名证书 + nginx 收敛**（纯基础设施，不动应用代码）
2. **应用 Host 分发 + 公司注册表**（含 acme 迁移与对账验证）
3. **控制台**（登录、建公司、列表、停用启用、重置管理员密码）
4. **品牌**（登录页系统名 + 公司名、浏览器 title）
5. **测试**：跨公司隔离、控制台鉴权、重置流程（requirements §12 第 6 条），全量回归现有 29 用例

## 9. 风险与回滚

| 风险 | 对策 |
| --- | --- |
| 所有公司共用一个进程，一家故障全停 | 单机 SQLite 场景可接受；systemd 自动重启；数据独立，可单独恢复某家公司 |
| 泛域名证书签发失败 | 保留现有按公司单证书配置作为回退 |
| 数据迁移出错 | 迁移前备份；旧实例 stop 但保留，切回旧 nginx 配置即整体回滚 |
| 控制台是高权限入口 | 独立子域名 + 强密码 + 锁定策略；PENDING-09 决定是否加二次验证 |

## 10. 明确不做的事

- 不做公司间数据共享或平台级汇总报表。
- 不做公司自注册、自助开通（开公司永远是万顺行为）。
- 不做控制台操作公司业务数据（控制台只管公司与账号）。
- deploy.sh 保留为首装与应急工具，不再用于日常开公司。
