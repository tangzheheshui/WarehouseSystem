# 仓库管理系统需求文档 V2.0

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 更新日期 | 2026-08-29 |
| 适用范围 | 一家公司内部的多项目仓库管理 |

## 1. 目标

系统为 Web 版仓库管理系统。一套部署服务一家公司，公司内可创建多个项目；不同公司独立部署、独立数据库。

## 2. 已确认规则

1. 原仓库人员和项目管理人员合并为 **项目管理员**。
2. 商品档案、仓库档案为公司级共享数据，各项目共用。
3. 库存、单据、拣货单、库存流水、模板、操作日志按项目隔离。
4. 库存查询结果不保存、不生成结果单编号，只支持当前条件查询和 Excel 导出。
5. 到期日期由生产日期加保质期天数自动计算，入库模板不填写到期日期。
6. 大单位、中单位、标准单位不做换算；库存作业使用标准单位数。
7. 提供的库存明细 CSV 作为项目历史库存初始化数据导入。

## 3. 角色与权限

| 功能 | 管理员 | 项目管理员 |
| --- | --- | --- |
| 商品信息录入 | 可以 | 不可以 |
| 仓库信息管理 | 可以 | 不可以 |
| 创建项目 | 可以 | 不可以 |
| 创建用户并授权项目 | 可以 | 不可以 |
| 入库管理 | 不可以 | 可以 |
| 出库管理 | 不可以 | 可以 |
| 库存查询和导出 | 不可以 | 可以 |
| 拣货单 | 不可以 | 可以 |
| 模板管理 | 不可以 | 可以 |
| 操作日志 | 不可以 | 可以 |

管理员页面以项目列表和用户列表为主，可进入基础配置入口；不显示模板、入库、出库作业入口。

## 4. 管理员功能

### 4.1 商品信息

字段：货品编号、货品名称、规格、标准单位、状态。

1. 货品编号公司内唯一。
2. 货品编号、货品名称必填。
3. 被库存或单据引用的商品不删除，只能停用。
4. 停用商品不能用于新入库和新出库。
5. 项目入库必须使用管理员维护的商品档案。

### 4.2 仓库信息

层级：仓库 / 库区 / 货区 / 货位。

1. 仓库名称公司内唯一。
2. 完整货位按四段显示。
3. 已有库存的结构不删除，只能停用。
4. 入库必须选择有效仓库和货位。

### 4.3 项目管理

字段：项目名称、状态、项目说明。

1. 项目名称公司内唯一。
2. 停用项目不能新增入库、出库或修改模板。
3. 历史库存、单据、模板和日志仍按项目保留。

### 4.4 用户管理

字段：姓名、姓名全拼、手机号、角色、所属项目、状态。

1. 姓名全拼是登录用户名，公司内唯一，格式为 2-50 位小写字母。
2. 手机号仅作为联系方式，不用于登录。
3. 密码 8-20 位，必须包含字母和数字。
4. 首次登录强制修改密码。
5. 连续 5 次登录失败锁定 10 分钟。
6. 管理员可创建、修改、停用用户，重置密码，调整项目授权。
7. 取消授权后，项目管理员立即失去对应项目访问权限。

## 5. 项目管理员功能

### 5.1 入库管理

项目管理员下载当前项目模板，填写 Excel 后上传。

入库模板字段：货品编号、货品名称、规格、标准单位、生产批号、生产日期、保质期（天）、入库日、标准单位数、仓库、库区、货区、货位、品质标记、采购单号、备注。

规则：

1. 货品必须已建档且启用，名称、规格、标准单位必须与档案一致。
2. 仓库、库区、货区、货位必须存在且启用。
3. 到期日期由生产日期加保质期天数自动计算。
4. 同项目、同货品、同生产批号、同货位的数量累计。
5. 任一行错误则整单拒绝，不修改库存。
6. 成功后生成入库单、库存明细、库存流水和操作日志。

### 5.2 出库管理

出库模板字段：货品编号、货品名称、标准单位数、备注。

1. 只校验和扣减当前项目库存。
2. 可用库存 = 库存总数 - 分拣占用数 - 移动占用数。
3. 品质标记为扣留或禁止出库为是的批次不能出库。
4. 同一货品多行按累计数量校验。
5. 库存不足时整单拒绝。
6. 出库按入库日先进先出分配批次，并生成拣货单。

### 5.3 库存查询

查询条件：仓库、库区、货区、货位、货品编号、货品名称、生产批号、品质标记、禁止出库。

页面展示商品汇总、批次明细和库存流水。查询结果可导出 Excel，但不保存查询历史。

### 5.4 模板管理

1. 模板分入库、出库两类，按项目隔离。
2. 项目管理员可修改中文列名、非系统必填字段和启用状态。
3. 保存后版本号加一，历史单据保留当时版本号。
4. 停用后不能下载和导入，历史数据不受影响。

### 5.5 操作日志

项目管理员查看所属项目日志。日志包含时间、操作人、操作类型、内容、项目，记录入库、出库、拣货完成、模板变更、历史库存导入等关键操作，不允许修改或删除。

## 6. 历史库存初始化

管理员在项目管理页选择空项目上传 CSV。CSV 使用用户提供的中文字段，支持 UTF-16 编码、Tab 分隔、Excel 公式形式文本和常见日期格式。

导入规则：

1. 历史库存仅允许对无库存项目执行一次。
2. 系统自动补齐不存在的商品、仓库和货位档案。
3. 保留库存总数、分拣占用数、移动占用数、品质标记、禁止出库、采购单号和日期。
4. 忽略 CSV 中的可用库存列，由系统重新计算。
5. 大单位、中单位字段仅作为源文件兼容字段，不参与换算和入库作业。
6. 导入成功生成一张历史导入单和对应库存流水。

## 7. 部署与访问

1. 访问地址使用公司目录前缀，例如 `http://193.112.26.217/acme/`。
2. 公司标识使用英文小写字母、数字或连字符。
3. 多家公司共用服务器 80 端口，Nginx 按 `/公司标识/` 转发。
4. 每家公司有独立应用目录、数据库、 systemd 服务和内部端口。
5. 登录态、接口和静态资源按目录前缀隔离。

## 8. 非功能需求

1. 单次 Excel 导入不超过 500 行、5MB；历史 CSV 不超过 5000 行、12MB。
2. 密码 PBKDF2 加密存储，会话 24 小时有效。
3. 接口校验登录、角色和项目授权。
4. 项目管理员不能通过修改请求参数访问未授权项目。
5. 页面、模板、导出文件的用户可见字段使用中文名称。
6. 自动化测试覆盖权限、项目隔离、导入、迁移、历史库存和路径前缀。

## 9. 验收标准

1. 管理员能维护商品、仓库、项目、项目管理员和项目授权。
2. 管理员页面不显示模板、入库、出库功能。
3. 项目管理员只能访问被授权项目。
4. A 项目用户不能查询、导入、导出 B 项目数据。
5. 到期日期自动计算正确。
6. 出库按可用库存校验，按先进先出扣减，扣留和禁止出库批次不能出库。
7. Excel 任一行错误时整单回滚，并显示行列级错误。
8. 历史 CSV 可完成一次性初始化。
9. 多公司目录访问互不影响。
10. 自动化测试通过。
